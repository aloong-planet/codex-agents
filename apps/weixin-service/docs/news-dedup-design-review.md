# 新闻去重设计审查

## 结论

方案可以实现。审查后补强如下：

1. **只在摘要后过滤无法满足目标。** 必须把研究拆成发现与摘要两阶段，本地过滤位于两者之间。
2. **不能只靠 prompt 排除历史。** 历史以哈希传入本地过滤；prompt 不需要接触庞大的历史 URL 列表。
3. **不能用标题组成身份。** 标题是展示字段，会翻译和修改；身份只用规范 URL。
4. **不能把所有 query 都删除。** HN item ID 等 query 有语义，只删除明确追踪参数。
5. **摘要已生成但归档失败不能丢缓存。** 否则重试会再次付出摘要成本；账本必须先保存 preview 与 summarized key，再尝试归档。
6. **同日自动任务必须复用手动 preview。** 否则同一天先预览后定时仍会重复研究。
7. **HN 当前热榜优先于跨日去重。** HN 每日重新核验官方前 10 名，按顺序取得最多 5 条可读且可归档的文章；单篇失败剔除并顺延，普通新闻继续使用持久历史去重。
8. **语义事件去重不能冒充确定性文章身份。** 不同来源可能包含独立证据，本版只在 prompt 中要求避免同事件占满榜单，不做高风险硬删除。
9. **跨栏目确定性去重与并行延迟存在取舍。** 若普通新闻和 HN 同时摘要，就无法在摘要前知道另一栏已选文章；本版按 HN→普通新闻串行，把 HN key 加入普通新闻排除集。接受延迟增加，各 Codex 子任务仍独立并受 240 秒超时约束。

## 已拒绝方案

- 继续用 `URL + 标题` 的发送后哈希：无法阻止摘要生成，且标题变化会漏判。
- 把最近 URL 全塞进 prompt：不可扩展且非确定性。
- 删除所有 URL query：会错误合并 HN 条目、论文版本或分页。
- 用标题相似度硬删除：中文翻译、版本号和同事件不同报道都容易误判。
