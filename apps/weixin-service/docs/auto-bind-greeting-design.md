# 扫码后自动绑定与首次问候设计

## 目标

用户完成真实腾讯 iLink 扫码连接后，不再手动勾选或点击“确认会话与目标”。Demo 持续监听该次连接账户的真实用户文本入站；收到第一条后自动：

1. 选中消息所属的直连账户与发送目标；
2. 将会话标记为可发送；
3. 使用该条消息携带的真实 `context_token` 回复固定问候：`你好，微信连接已成功，现在可以直接给我发指令了。`；
4. 在网页明确显示等待、发送中、渠道接受或失败状态。

“渠道接受”不宣称手机已经收到。问候失败或结果未知时不自动重试。

## 已确认事实

- `DirectIlinkChannel.monitor` 在解析到 USER 文本和非空 `context_token` 后，先保存最新上下文与目标元数据，再发布 `InboundTextEvent`。
- `InboundTextEvent.replyText` 闭包捕获该条入站的 `accountId`、`target` 与 `context_token`，不会在异步发送时误读另一条消息更新后的 token。
- `onInboundText` 只发布 USER 文本，并过滤本进程近期出站 `client_id`，因此问候本身不会直接形成回声循环。
- 扫码确认后的账户 ID 只能从登录完成后刷新得到的 channel snapshot 获得；登录事件本身不携带账户 ID。

## 模块边界

### `AutoBindingStore`

专门持久化自动绑定生命周期，不保存凭据、token 或消息正文。接口只暴露：

- `load(): AutoBindingRecord`
- `save(record): void`

记录包含：待绑定账户、最近一次绑定的目标、触发入站事件键、状态与时间。文件位于 Demo 私有状态目录，与 iLink 凭据文件分离。

### `DemoService`

仍是页面状态与用户动作的唯一编排层：

- 登录完成后，从 channel snapshot 解析唯一可用的新账户并持久化 `awaiting_inbound`；
- 订阅 `onInboundText`；只消费与待绑定账户一致的第一条事件；
- 在发起问候前先把待绑定状态持久化为 `sending`，从而关闭重复发送窗口；
- 自动设置 `selectedAccountId`、`selectedTarget` 与 `phase=ready`；
- 用事件级 `replyText` 发送一次问候，并落盘最终 `accepted` 或 `failed`。

该接口保持较深：HTTP 与浏览器只读取统一公开状态，不接触 token、持久化细节或 iLink API。

## 状态机

```text
login connected/already_connected
  -> awaiting_inbound(accountId)
  -> first matching USER text
  -> sending(accountId,target,eventKey) [先持久化，后发送]
     -> accepted
     -> failed (rejected/auth_stale/unknown；均不自动重试)
```

进程在 `awaiting_inbound` 时重启会继续等待。进程在 `sending` 时崩溃，恢复后保持失败/结果未知语义，不重发，以避免重复消息。

## 用户操作序列与失败模式

1. **打开已有配置但未重新扫码**：不会自动问候旧目标；只有完成一次新登录才布防。
2. **扫码完成但尚未发消息**：页面显示“等待首条微信消息”，不发送任何内容。
3. **扫码后发送首条文本**：自动绑定该消息的账户和目标并发送一次问候。
4. **短时间连续发送多条**：第一条先持久化消费；后续消息不会再次触发问候。
5. **收到其他账户消息**：与待绑定账户不符，不消费本次布防。
6. **服务在等待期间重载**：从安全文件恢复等待状态，仍由下一条匹配消息触发。
7. **服务在问候发送中崩溃**：不自动重发；页面恢复为结果未知/失败提示。
8. **iLink 拒绝、凭据失效或网络超时**：会话目标仍已自动识别，但问候显示失败；不自动重试。
9. **重新发起扫码**：覆盖旧的等待布防；只允许最新完成登录的账户触发。
10. **已有 Codex 自动回复已启用**：首条消息可能同时进入 Codex 服务；自动绑定问候独立发送一次，不改变 Codex 开关。

## 页面变化

- 删除手动入站确认复选框与“确认会话与目标”按钮。
- 步骤 2 显示自动绑定状态和说明；保留目标下拉框与本地别名设置，用于多目标管理。
- 渲染时优先采用服务端 `selectedAccountId/selectedTarget`，确保自动绑定后页面立即指向实际来信目标。
- 测试发送按钮在自动绑定完成后启用；欢迎消息反馈与手动测试发送反馈分开。

## 验证标准

- 单元测试证明：登录后首条匹配入站会自动绑定并仅问候一次；其他账户不触发；并发入站不重复；失败不重试；等待状态可恢复；未重新登录不会问候旧目标。
- HTTP/DOM 测试证明：页面没有手动确认控件，自动绑定状态可见，服务端所选目标在多个候选中仍被选中。
- 全量执行 `pnpm lint`、`pnpm test`、`pnpm build` 与本地 fixture e2e。
- 真实端到端最后一步必须由用户扫码并从微信发消息；验证以网页显示渠道接受且手机实际收到为准。
