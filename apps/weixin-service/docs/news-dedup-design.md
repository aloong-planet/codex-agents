# 新闻文章身份与摘要去重设计

## 目标与边界

同一篇文章不因跨日热榜、重复点击预览、标题微调或常见追踪参数而再次生成摘要、重复归档或重复发送。用户明确要求跳过 TDD 红绿循环；实现后仍补充回归测试并运行全量验证。

本版把“同一篇文章”定义为规范化后 URL 相同。不同媒体对同一事件的独立报道不强行合并；研究 prompt 继续要求排除重复报道，但语义事件聚类不作为确定性身份，以免误删不同事实来源。

## 深模块与 seam

`AiNewsResearcher.generate(window)` 仍是 scheduler 唯一需要理解的 interface，但 `window` 新增持久历史中的 `excludedArticleKeys`。研究模块内部隐藏两阶段实现：

1. **发现阶段**：实时搜索只输出候选元数据，不生成摘要；HN 候选仍来自官方 API。
2. **本地身份阶段**：规范化 URL，计算 `articleKey=sha256(canonicalUrl)`，删除批内重复和历史已摘要候选。
3. **摘要阶段**：只把剩余候选交给 Codex 打开正文并生成结构化摘要；输出 URL 必须属于允许的候选集合。

调用方不需要理解搜索次数、URL 参数、HN 候选或输出白名单。删除该模块会使这些规则重新散落到 scheduler，因而该 module 有足够 depth。

## URL 规范化

只接受无用户名/密码的 HTTPS URL：

- host 小写，移除 fragment；
- 移除默认端口和末尾多余 `/`；
- 删除 `utm_*`、`fbclid`、`gclid`、`mc_cid`、`mc_eid` 等明确追踪参数；
- 其余 query 按键值排序并保留，因为 HN `item?id=`、论文版本或文章分页可能具有语义；
- 不凭猜测合并不同域名、镜像或转载。

正文页以后若能可靠提供 `<link rel=canonical>`，可在归档模块补充别名映射；本版不让网络抓取参与文章身份计算，避免把去重再次放到摘要之后。

## 持久历史与迁移

`DailyAiNewsState` 增加 `summarizedArticleKeys`，保存已经成功生成并缓存摘要的规范 URL 哈希。旧的 `seenItemKeys` 保留用于兼容已有状态和发送历史，但不再承担新摘要去重。

- 历史上限 100,000 个键，约可覆盖数十年 Top 10 日报；超限时仅淘汰最早的键，不再采用 500 条滑动窗口导致旧文章过早复活。
- 新摘要一生成就连同 preview 和 key 原子写入私有账本；归档失败时保留缓存，后续只重试归档，不重新摘要。
- 同日已有 preview 时，手动预览和自动日报复用它，不再次研究；发送成功后仍沿用现有发送幂等账本。
- 旧状态没有规范 URL 历史，升级后的第一次可能无法识别升级前更早的重复；当前 preview 与保留 runs 中的 URL 会在加载时回填规范 key。

## 用户操作与失败路径

1. 同日反复点击“生成今日预览”：复用已经生成的 preview，只重试必要的归档，不调用 Codex。
2. 同一 URL 次日仍在 HN：发现阶段后由本地 key 删除，不进入摘要阶段。
3. URL 只有 UTM、fragment 或参数顺序不同：归一为同一 key。
4. 同一批 general 与 HN 指向相同 URL：本地合并，优先保留 HN 栏目标记，摘要只生成一次。
5. 候选全部重复：返回空 digest，日报诚实显示无新内容，不因 HN 为空而失败。
6. 发现阶段失败或搜索不足：整次研究失败。
7. 摘要阶段返回候选外 URL：整次研究失败，防止模型绕过本地排除。
8. 摘要完成后归档失败：缓存摘要和 key；不发送，后续同日重试归档但不重新摘要。
9. 同 URL 正文实际更新：本版仍视作同一文章，不重复摘要。若以后需要更新追踪，应新增独立的正文版本机制，而不是削弱文章身份。

## 验证

- 规范化 URL 与稳定 key；
- general 两阶段调用顺序及候选白名单；
- HN 在摘要前过滤；
- 批内跨栏目去重；
- 同日 preview 复用；
- 跨日历史 key 在研究前传入；
- 旧状态自动回填；
- lint、typecheck、全量单元/集成、build、fixture 浏览器 E2E。
