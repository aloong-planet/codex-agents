# 微信日报单消息精简设计审查

日期：2026-08-15

## 结论

方案可行，但“每条 300 字”不能直接作为发送实现：5×300 已耗尽渠道总上限，日期、栏目和来源会必然触发第二段。应采用“总预算 1,500 + 每条上限 280”的双门禁。

## 审查发现与修正

1. **直接缩短 `NewsItem.summary` 会损害 Vault 细节检索。** 短版只在 `formatNewsDigest()` 生成，原始 digest 和归档保持详细。
2. **只改提示词不能形成确定保证。** 模型长度是软约束；发送前必须用确定性 code-point 预算二次压缩。
3. **按 JavaScript `length` 会错误计算 emoji。** 所有预算和截断统一使用 `Array.from()`，与微信分段器一致。
4. **固定每条 280 仍需计算栏目开销。** 先扣除日期、实际栏目标题和分隔空行，再取 `min(280, 平均可用预算)`。
5. **只保留摘要开头会再次丢失结论。** 结构化摘要分别抽取背景、进展、第一条证据和影响，均衡压缩后再合并。
6. **来源很长会挤掉摘要。** 标题和来源分别设内部上限；摘要获得剩余预算，最终区块再做硬校验。
7. **不足 5 条不应重新变成长文。** 每条 280 是稳定上限，不因只有 1–4 条而扩张。
8. **面板和真实发送若用不同格式会误导。** 保持所有调用方继续经过同一个 `formatNewsDigest()` 接口。
9. **极端多条历史 digest 可能让平均预算过小。** 兼容路径仍保证总长；当前自动流程最多 5 条，测试重点锁定 5 条完整保留和单段发送。
10. **截断不能伪装成完整内容。** 任一字段缩短都加 `…`，用户可到 Vault 原文继续追问。

## 审查后的接口

- 不新增公开类型或字段。
- `formatNewsDigest(digest): string` 接口不变，但新增不变量：返回值不超过 1,500 Unicode code points。
- `NewsArchive.archive(digest)` 与研究模块接口完全不变。
