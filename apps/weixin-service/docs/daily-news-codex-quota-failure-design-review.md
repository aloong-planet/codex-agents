# 日报 Codex 额度失败分类设计审查

日期：2026-08-20

## 审查结论

方案可以实施，但必须遵守以下修正，避免把所有非零退出误判成额度耗尽。

## 已识别风险与修正

1. **只看 stderr 会漏掉 `--json` stdout 错误**
   - 修正：runner 同时扫描两路，只输出固定安全标记；不得把 stdout 尾部拼入异常。

2. **把 429 与套餐额度耗尽混为一谈**
   - 修正：分别使用 `codex_usage_limit` 与 `codex_rate_limit`，中文文案不宣称相同恢复机制。

3. **成功覆盖失败后再次无法诊断**
   - 修正：保留一个有界、结构化的 `lastFailure`，而不是保存原始异常或无限历史。

4. **历史状态迁移风险**
   - 修正：`lastFailure` 可选；旧 v2 状态照常读取，不从通用 `codex_process` 反推历史额度错误。

5. **通知泄露账户或原始服务错误**
   - 修正：通知只使用固定 enum label；原始 stderr/stdout 仅用于进程内匹配，不落盘、不上屏、不发微信。

6. **失败通知发送失败形成递归通知**
   - 修正：沿用既有 failure-notice 状态机，不新增第二层微信通知或自动循环重发。

7. **今天已经最终成功却再次补发**
   - 修正：本次修改仅影响未来失败分类与安全诊断；不触发今天日报或历史通知发送。

## 审查后的成功标准

- 已知额度错误不再显示通用“进程失败”。
- 未知错误仍保持未知，不被猜成额度问题。
- 后续成功不丢失最近一次安全失败原因。
- 不改变发送与重试次数语义。
