# Obsidian 新闻归档设计审查

## 审查结论

方案可实现，但实现前补强以下约束；补强项已回写设计正文：

1. **不能让 Codex 产出的 URL 直接访问内网。** 正文抓取是新的服务端请求能力，必须对初始 URL 和每次重定向做公网地址门禁，并且不发送任何认证信息。
2. **摘要必须最后写。** 如果先写索引再抓正文，用户会点到不存在的文件；归档顺序改为正文成功落盘后再发布摘要。
3. **单篇失败与归档失败要区分。** 用户选择“单篇跳过继续”，不等于 Vault 整体写入失败也可发送；后者会使微信摘要与本地事实不一致，必须阻止发送。
4. **自然代词不能只靠关键词搜索。** “第二条/这篇”需要先读最近摘要，再解析序号或候选；只把原消息交给全文搜索会稳定失败。
5. **调度器已有重复与未知发送约束不能被破坏。** 归档不改变 send ledger；accepted 不重发，unknown 不重试，明确拒绝仅在新入站后补发一次。
6. **新闻读取不能复用全 Vault 搜索结果。** 即使是只读，普通笔记也不应进入新闻问答；工具与底层搜索都必须硬限制在 `news/`。
7. **同日重跑不能删除旧文件。** 新摘要可能改变 Top 10；删除会破坏用户已打开的链接和手工批注。本版只新增/复用正文并刷新摘要，历史孤立文件保留。
8. **正文超限不能静默截断。** 截断文件会被误认为完整正文；应把该篇记为未归档。
9. **直接把浏览器 profile 接入归档会泄露登录态。** 动态页面回退必须使用全新的无痕 context，不加载用户 profile、Cookie 或扩展。
10. **只检查顶层 URL 不足以防 SSRF。** JavaScript、重定向和 XHR 都可能访问新地址；浏览器的每个网络请求都必须经过同一公网门禁，且非 GET 请求直接阻止。
11. **所有抓取失败都启动浏览器会掩盖真实错误并扩大攻击面。** 只有静态 HTML 已成功读取、但 Readability 报“页面没有可读取正文/正文过短”时回退；HTTP 错误、非 HTML、超限和门禁失败维持原错误路径。
12. **每篇都浏览器渲染会显著拖慢日报。** 静态抓取保持首选；仅动态壳页支付浏览器成本，且导航与正文等待均有硬超时。
13. **浏览器渲染成功不等于可无限落盘。** 最终 DOM 仍执行 2 MB 上限、Readability 清洗和既有 100 KB Markdown 写入限制。

## 被拒绝的替代方案

- 让 Codex 在新闻 JSON 中直接输出“全文”：内容不可验证、容易把模型改写当原文，且结构化输出大小不稳定。
- 把 URL 和全文抓取写进 scheduler：会把网络安全、HTML 清洗和 Vault 路径规则扩散到调度逻辑。
- 仅扩大现有 `obsidian_search_markdown` 的触发词：会把自然新闻追问授权成整个 Vault 的搜索权限。
- 本地归档不足时自动联网：与用户选择冲突，也会让回答不可复现。
