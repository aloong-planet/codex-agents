# 微信图片外发权限设计审查

## 审查发现

1. **只补“回发”关键词不完整**：实际图片和指令常分成两条消息，第二条没有附件路径。设计必须同时解决近期图片定位。
2. **不能让模型决定授权**：模型可选择候选图片，但授权仍由宿主根据当前用户消息判定，工具调用本身不构成授权。
3. **近期图片不能跨聊天**：索引键必须同时包含账户与目标，避免第二目标引用第一目标的文件。
4. **不能无限积累路径**：采用 10 分钟 TTL 与每聊天 5 张上限；每次读取和写入都清理过期项。
5. **模型需要可调用的路径**：上一轮图片只作为视觉输入时，模型未必能可靠恢复本地路径。turn binding 必须提供内部候选提示。
6. **重启恢复不应顺手扩大范围**：已有私有媒体文件保留 7 天，但本阶段不新增持久化近期索引。重启后要求引用或重新发送图片，避免把历史媒体默认重新授权。
7. **发送结果仍非事务**：上传、媒体发送与 caption 各自进入 effect ledger；`unknown` 不自动重试。

## 结论

设计在保持显式用户授权和跨目标隔离的前提下，覆盖“先发图、后发回传指令”的真实操作。复杂度集中在 `WeixinMediaToolHost`，调用方 interface 比原有布尔门禁更小、更可靠，可以进入实现。
