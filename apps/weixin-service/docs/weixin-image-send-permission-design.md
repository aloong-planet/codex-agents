# 微信图片外发权限与近期图片设计

## 目标

用户在当前微信消息中明确要求发送图片时，Codex 可以把当前、引用或同一聊天近期收到的图片发送回该微信目标。授权只来自用户当前消息，不由模型自行扩大。

## 用户操作序列

1. 用户发送图片，随后发送“把刚才的图片回发给我”。
2. 宿主按 `(accountId, target)` 记录近期入站图片，只保留最近 10 分钟、最多 5 张。
3. 媒体 host 识别当前消息中的明确发送动作和图片/指代词，为该 turn 绑定一次性能力。
4. 媒体 host 将可选近期图片的受控本地路径作为内部提示交给 Codex；路径不展示给微信用户。
5. Codex 调用 `weixin_send_media` 后，host 再校验路径、目标、有效期、文件类型、大小和授权根。
6. turn 结束立即撤销能力；真实发送结果继续由 durable effect ledger 记录。

## 深模块与 interface

`WeixinMediaToolHost.bind(threadId, event, roots)` 返回一个 turn binding：

- `promptLines`：只供 Codex 使用的近期图片候选，不包含 token 或目标标识；
- `release()`：撤销本 turn 能力。

调用方不再计算或传入 `allowed`。动作词、图片指代、近期媒体范围、TTL、数量、跨目标隔离和路径门禁全部隐藏在 host implementation 内。

## 授权规则

- 当前消息必须包含明确发送动作：发送、发给、回传、传给、回发、发回或等价英文。“发来/发过来”只描述入站来源，不单独构成外发授权。
- 同时必须包含图片/媒体词或明确指代，或者当前/引用消息本身携带附件。
- 当前与引用附件沿用既有权限；近期引用本阶段只扩展图片。
- 近期图片只在相同 `accountId + target` 内有效，10 分钟后失效，每个聊天最多 5 张。
- 不允许远程 URL、跨目标路径、符号链接、目录或超过 100 MiB 的文件。
- 没有明确授权时即使模型调用工具也 fail closed。

## 失败模式

- “看看这张图”等无外发动作：只读处理，不授权发送。
- “把刚才的图发回来”但没有近期图片：工具不可用，回复应说明没有可发送图片。
- 多张近期图片且指代不清：模型不得假称成功；可请求用户引用具体图片。
- 服务重启：进程内近期索引清空；用户可引用原图重新建立确定上下文。本阶段不新增第二份媒体持久索引。
- 腾讯上传或发送超时：effect 标记 `unknown`，不自动重发。

## 验证

- “回发图片”能获得一次性能力。
- 图片消息后跟文字回发指令，近期路径可被工具发送。
- 无明确动作、过期、跨账户或跨目标均拒绝。
- 当前/引用附件及授权根的原有发送能力不回归。
- 真实渠道由用户发送图片与指令后验证；只报告渠道 accepted，不假称手机收到。
