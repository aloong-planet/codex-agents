# Codex App Server 当前任务交互探针设计审查

审查对象：`docs/app-server-bridge-design.md`

## 结论

方案可进入最小实现。它验证的是用户要求的“先不 fork、先跑通当前任务交互”，同时没有
提前把不可信微信正文或工具审批接入自动路径。

## 审查发现与约束

1. **turn override 会污染后续任务默认值。** App Server 文档说明 turn 级模型、目录和沙箱
   override 会成为后续默认值；因此探针不得传这些字段。
2. **独立 App Server 对桌面进程的内存状态不可见。** `thread/list` 显示的是自身 runtime
   状态，不能把 `notLoaded` 当成桌面任务空闲证明；并发冲突必须失败而非重试。
3. **恢复成功不等于交互成功。** 必须实际 `turn/start` 并收到匹配 turn 的非空最终回复。
4. **固定 prompt 仍可能意外触发工具。** 客户端必须拒绝所有 server-initiated 请求，且不能
   依赖提示词作为唯一安全边界。
5. **输出 delta 可能混入其他 turn。** 只能聚合 `turnId` 与本次响应一致的事件。
6. **直接打印完整协议会泄露历史 preview。** 生产探针只打印阶段和最终固定回复；不得记录
   `thread/list`、原始 JSON-RPC、任务历史或配置。
7. **stdio 子进程可能悬挂。** 所有终态与超时必须关闭 transport，且 close 应幂等。

## 实现门禁

- 先写失败单测，再实现客户端状态机。
- 真实模型探针仅运行一次；若遇到当前 turn 冲突，不自动补发。
- 验证期间不操作微信、不修改凭据、OpenClaw 配置或插件源码。

## 实测审查结论

客户端、transport 与固定探针均已实现并通过确定性测试，但当前桌面任务的真实恢复在
`thread/resume` 阶段被 active-writer 门禁拒绝。该结果符合设计中的并发失败模式，不能将
“能列出任务”包装成“已打通交互”。本纵切保留为可复现诊断入口；在 writer 归属方案改变前，
不得接入微信自动回复。
