# Obsidian 新闻归档与微信追问设计

## 目标与已确认决策

每日新闻研究完成后，Demo 在本地 `demo` Obsidian Vault 中维护：

- `news/YYYY-MM-DD/摘要.md`：当天 Top 10 的结构化摘要与正文索引；
- `news/YYYY-MM-DD/<标题短名>-<稳定哈希>.md`：可取得且清洗后的文章正文。序号只属于当日摘要，排序变化不会改正文路径。

用户已确认：保存清洗后的完整正文；普通新闻单篇正文不可取得时跳过正文文件、继续当天任务并在摘要中标注；HN 从官方前 10 名顺延选取最多 5 篇，某篇正文不可取得时将该篇从最终榜单、摘要和微信正文直接剔除，不阻断其他新闻。微信发送一条最多 10 条的精简摘要；自然细节追问自动检索本地归档，不足时不自动联网。

不包含：绕过付费墙或登录、保存 Cookie/凭据/原始 HTML、自动联网补答、删除历史归档、改动腾讯插件或 OpenClaw 配置。

## 模块边界

新增深模块 `NewsArchive`，向调用方只暴露三类能力：

```ts
archive(digest): Promise<ArchiveResult>
search(query): Promise<NewsArchiveMatch[]>
read(path): Promise<NewsArchiveArticle>
```

它内部负责 URL 安全检查、正文抓取与清洗、文件命名、Markdown 渲染、同日重复运行的幂等处理，以及把所有读操作限制在 `news/`。调度器不操作路径或 HTML；微信服务不直接访问文件系统。

底层继续复用 `DirectMarkdownVault` 的无符号链接、原子更新、大小限制和 SHA-256 并发保护。为避免全 Vault 搜索泄露到新闻问答，底层增加受验证目录前缀约束的 `searchWithin("news", query)`。

`DailyAiNewsScheduler` 在研究成功、发送前调用 `archive(digest)`：

1. 逐篇抓取并创建正文；失败只记录到归档结果；
2. 最后写 `摘要.md`，只有已经成功存在的正文才生成内部链接；
3. 归档自身失败时，当次日报标记失败且不发送，避免微信声称存在一个实际未落盘的归档；
4. 微信发送仍沿用既有 accepted / unknown / pending_inbound 语义，不新增盲重试。

归档成功回执中的摘要路径、正文成功数和跳过数由调度器映射为公开状态；网页显示 `Vault：news/YYYY-MM-DD/摘要.md，正文 N/M`，但不公开原文 URL 或本地绝对路径。进程重启后通过既有 preview 回填重新获得该状态。

手动“生成今日预览”也会归档，但不会发送微信。当天再次生成时复用已有正文文件，并以 SHA-256 保护的更新替换 `摘要.md`；不会删除同日旧文件。

服务启动时也会对私有账本中最近一次成功预览做一次幂等回填，以便升级前已经研究出的当天内容进入 Vault；已有正文不会重新抓取，也不会因此发送微信。

## 正文抓取与清洗

`ArticleBodyFetcher` 只接受 `http:` / `https:` URL：

- 每次请求和每个重定向前解析主机，拒绝 localhost、环回、链路本地、RFC1918/ULA 等非公网地址；
- 手动跟随有限次重定向；超时、非 2xx、非 HTML、响应过大、正文过短均视为该篇不可归档；
- 不携带浏览器 Cookie、认证头或本地凭据；
- 用 Mozilla Readability 提取文章主体，再转为 Markdown；移除脚本、导航、表单、图片数据 URL 和事件属性；
- 正文文件含标题、来源、发布日期、原始 URL、抓取时间及清洗后的正文，不含原始 HTML。

静态 HTML 返回成功但 Readability 无法取得正文时，抓取模块内部使用一次受限的无痕浏览器渲染回退；`NewsArchive.archive()` 的 interface 不增加浏览器概念：

- 使用新的无痕 browser context，不继承用户 Cookie、登录态、扩展或本机浏览器 profile；
- 初始文档、重定向和所有子资源请求均重复执行公网地址门禁，拒绝非 HTTP(S)、认证 URL、localhost、环回、链路本地和内网地址；
- 只允许 GET，阻止下载、弹窗、Service Worker、图片、音视频与字体，保留页面正文渲染需要的脚本、样式和 XHR；
- `domcontentloaded` 后只等待有限时间内出现非空正文，再读取最终 DOM；最终 DOM 同样受 2 MB 上限和 Readability 清洗约束；
- 浏览器启动、导航、渲染或清洗失败仍按单篇“正文无法取得”处理，不使当天摘要失败。

静态抓取是首选路径；只有明确的“HTML 可达但正文不可读取”才启用浏览器，以免把 HTTP 状态、非 HTML、超限、DNS/SSRF 门禁等失败误当成动态页面。

单篇正文写入受现有 100 KB Markdown 写入上限约束；超限视为该篇失败，不截断成貌似完整的正文。

## 微信自然追问

现有 Obsidian 写入授权开关继续控制用户主动的普通 Vault 写操作。新闻问答新增两个只读动态工具：

- `news_search_archive({query})`：只返回 `news/` 下的匹配路径、日期、标题与来源；
- `news_read_archive({path})`：只允许读取 `news/` 下的 Markdown。

以下入站意图可在本轮临时授权这两个工具：提到新闻/日报/摘要/Hacker News/文章，或使用“第 N 条、这篇、那篇、细节、具体怎么做、依据、风险”等明显承接新闻摘要的问法。普通聊天不会获得新闻目录读取能力。

Prompt 明确要求：

- 自然追问优先读取最近的 `news/*/摘要.md`，用序号、标题、来源或关键词定位正文；
- 多个候选无法唯一判断时先让用户确认，不猜测；
- 只依据归档回答，并带上日期、标题和来源；正文未归档或证据不足时明确说明；
- 不因细节不足自动联网；用户另行明确要求实时检索时，才走既有联网能力边界。

动态工具清单属于专用 Codex task 的启动配置，因此线程 profile 从 `obsidian-v1` 升级为 `news-archive-v2`。首次加载新版时创建新的独立 task，避免恢复一个不知道新闻工具的旧 task；微信目标、转录和 Vault 写入开关继续保留。

## 用户操作序列与失败模式

### 定时日报

1. 08:30 前服务运行：等待定时器；到点开始研究。
2. 08:30 后当天首次恢复：立即补跑；已有同日 run 不重复。
3. 研究失败：不建假归档、不发送。
4. 部分正文失败：成功正文和摘要照常写入，摘要标记失败条目。
5. Vault 根不可用、摘要写入冲突或归档模块异常：当日 run 失败、不发送。
6. 归档完成后用户停用/切换目标：保留本地归档，不发送。
7. 发送明确拒绝：等待同一目标新入站后只补发一次既存摘要。
8. 发送超时/结果未知：不自动重发，归档仍可查询。
9. 进程在归档后发送前中断：恢复沿用现有 run 恢复规则；不会凭猜测重发。

### 手动预览

1. 点击生成：研究并归档；完成后页面显示预览，不发送。
2. 重复点击期间：仍由现有互斥锁拒绝第二次任务。
3. 同日再次成功：复用已归档正文、刷新摘要；不覆盖人工修改过且修订冲突的文件。

### 微信追问

1. “第二条具体怎么做”：读取最近摘要，唯一映射后读正文并回答。
2. “Nvidia 那篇的集中度如何”：按标题/正文检索，唯一命中后回答。
3. “这篇有什么风险”但上下文无法唯一定位：列出候选并请求确认。
4. 正文抓取失败或信息不在正文：明确说本地归档不足，不编造、不自动联网。
5. 恶意路径或越界路径：工具拒绝，不能读取 `news/` 外文件。
6. 新闻工具调用期间文件被修改：读取返回当前完整文件；写入逻辑仍受 SHA-256 并发保护。
7. 项目页的初始 HTML 只有 JavaScript 壳：静态 Readability 失败后启用受限浏览器渲染，再从最终 DOM 归档；仍无正文则保留“正文未归档”。

## 验证标准

- 单元：URL 公网门禁、HTML 主体转换、动态页面回退触发/不触发条件、稳定命名、单篇失败继续、摘要最后写入、同日幂等、news 范围搜索/读取、越界拒绝、自然追问授权与 prompt。
- 集成：scheduler 预览和自动日报都先归档再可发送；归档失败不发送；单篇失败仍发送并在摘要标注。
- 全量：lint、typecheck、Vitest、build、fixture 浏览器 E2E。
- 本地真实 Vault：对账本内已经生成的同日预览幂等重试归档，确认动态页面正文文件和摘要链接落盘；不重新研究、不触发真实微信发送。
