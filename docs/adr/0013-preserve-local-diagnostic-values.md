# ADR-0013: 本地诊断保留已采集原值

- 状态: 已接受（2026-09-13）

## 背景与问题

OTel 写入和读取的白名单会把新技术错误码改成 other，削弱排障证据。用户明确要求移除诊断脱敏逻辑，而不是持续补枚举。

## 备选项

1. **去除本地诊断白名单和 HMAC，保留已采集原值**：用户选择。
2. 继续维护白名单并新增错误码：不采用，仍会丢失未来新代码和字段。

## 决策

采用方案 1，取代 ADR-0012 的安全投影与 HMAC 选择；其定向网络 instrumentation、标准上下文、本地有界存储、无外部 exporter/传播头及业务真源隔离继续保留。

诊断入口接收到的字段、技术代码、名称与关联值不再脱敏；既有文件查询参数以原值代替指纹。OTel 嵌套属性使用 JSON 字符串适配，不将格式适配变成语义归类。SDK 已采集的 URL 不再清空；不新加请求头、请求/响应正文、文件正文或模型全文采集。工具对模型的安全错误契约和微信自然语言回执不变。

## 后果

- 正面：新错误码、参数和阶段不再因白名单缺项丢失，正式 reader 可直接查询。
- 负面：本地日志可能含路径、查询、账户/目标标识、URL 及其参数；共享前需要人工审查，不宣称日志已脱敏。
- 限制：记录与队列预算仍可能丢弃超大数据；历史 other 或 HMAC 无法恢复原值；诊断不改变业务权限、不触发重试、不证明手机收件。

## 已确认的采集范围扩展（2026-09-14）

用户选择先启用官方 fs instrumentation 和 runtime-node metrics，不手动补其余 fs 操作。沿用本地私有有界出口，metrics 独立成信号并保留 SDK 聚合语义；无网络 exporter、正文采集或业务权限扩张。主服务活动上下文与沙箱进程各自加载插件，沙箱使用固定自包含预加载产物和独立诊断通道，避免放开依赖目录读取或污染业务 stdout。

这里不建立请求级或父子代际语义关联。集中记录 init、execute、timeout、exit 与代际关系的沙箱 instrumentation 明确留待下一项；不会在文件业务算法中逐点手动埋入。代价是现阶段 fs Span 和进程指标只能证明底层操作及进程活动，不能独立还原一次请求的完整阶段。
