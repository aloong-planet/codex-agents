# ADR-0002: 模块权限在安装和设置阶段配置

- 状态: 已被 ADR-0010 取代

## 背景与问题

模块需要访问本地目录，但运行中临时请求权限会让用户在对话途中处理安全配置，也会让无人值守任务停在审批状态。用户希望安装模块时一次看清权限，之后通过固定设置页调整，同时保持读取、写入和执行边界明确。

## 备选项

1. **按模块、按目录持久配置独立读写权限，运行时只校验**
2. 任务运行到受限步骤时临时申请并等待批准——打断交互，也无法保证后台任务有人处理
3. 使用全局安全档位一次授权所有模块——无法表达不同模块、不同目录的最小权限
4. 把文件执行做成可配置权限——当前没有必要的受控执行边界，首版直接禁止

## 决策

选定**方案 1**：模块安装或首次启用时展示资源目录，所有已列目录默认预选读取、默认不选写入，用户保存后才授权。用户可增加目录并在设置页逐目录调整读写；文件执行始终禁止。权限不足的运行不申请升级，而是在 effect 前终止并引导用户调整设置后手动重试。

## 后果

- 正面：权限边界可预见、可审计，不依赖对话中的模型判断或用户恰好在线；读写可以按模块和目录最小化授权。
- 负面：权限不足不会在原任务内自动恢复，用户需要离开运行详情、修改设置并手动重试。
- 中性：微信回复不是模块文件权限；当前渠道上下文与 schedule 目标仍由各自配置和渠道规则约束。
