# ADR-0011: 使用本地有界 OTel 证据，不另建诊断平台

- 状态: 已被 ADR-0012 取代

## 背景与问题

既有运行记录和工具摘要分散，排查微信回合、并行工具、待选恢复和外发耗时需要手工关联。未结束操作不能仅靠完成时导出的 Span 留下停点证据；诊断本身不能扩大正文采集或影响业务。

## 备选项

1. **OTel API/SDK + 薄本地文件出口与只读查询**：采用，满足当前单机排查，控制隐私和部署成本。
2. Collector 加 Jaeger/Phoenix 等独立平台：本期暂缓；需要集中检索、多机运维或团队共享时重新评估。
3. 再建诊断 SQLite 和独立页面：不采用；重复既有 Run/Effect 真源，增加保存与清理职责，用户已选择先只接 OTel。

## 决策

采用方案 1。手动埋点观察既有入站、App Server 可见阶段、Tool Host 和 Durable Workflow；不改变主模型语义 Owner。使用真实 OTel Span 与异步上下文关联，不注册全局自动采集或外部 exporter。

薄出口只保存版本化安全投影 JSONL，并非 OTLP JSON wire format。完成 Span 与开始/进展 checkpoint 分文件；开始证据不能等 Span 结束才导出。跨回合用非授权性的宿主 Run UUID 关联，账户、目标、消息、Effect 和查询使用进程内 HMAC；文件、scope 和授权原始引用不导出，密钥不落盘。

文件在 macOS 用户日志目录的专用子目录，按小时或大小封口，按封口时间和总容量淘汰。写入队列、记录和查询都有上限。读写失败只影响诊断，不触发业务重试或权限变更；正常退出有限等待，硬杀和断电不承诺无损。

## 后果

- 正面：无需独立观测服务即可关联停点、并发和领域失败，既有业务状态不迁移。
- 负面：需要维护薄文件格式、清理器和读取器；非标准 OTLP 文件不能直接冒充 Collector 文件输入。
- 限制：清理和查询预算可能使证据不完整；进程停止期间不能执行清理。HMAC 不能解释查询词语义；模型内部排队与推理无法从宿主事件细分。渠道接受不证明手机收到。
- 不建立跨天悬挂 Span；Run/Effect/文件操作日志继续是执行与恢复真源，不以 Trace ID 作为幂等键。
