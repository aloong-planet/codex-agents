# ADR-0014: 保留运行时指标，不启用 fs 自动追踪

- 状态: 已接受（2026-09-14）

## 背景与问题

本地 fs 逐操作诊断在两个隔离真实模型样本中占诊断字节约 64%，高频成功操作产生较多记录。用户在分析后明确取消 fs 插件，只继续 runtime metrics。

## 备选项

1. **不启用 fs 插件，保留 runtime metrics**：用户选择。
2. 过滤快速成功的元数据操作、保留错误及慢调用：此前建议，用户未采用。

## 决策

采用方案 1，取代 ADR-0013 的“已确认的采集范围扩展”中启用 fs 的部分。ADR-0013 的原值保留、网络观测、本地有界存储及其他隔离边界继续有效。

主服务与文件沙箱只增加官方 runtime-node 指标，不加载 fs instrumentation。沙箱指标仍使用固定自包含预加载产物和独立有界通道；不增加用户目录授权。沙箱 init、execute、timeout、exit 与代际关联的集中 instrumentation 留待下一项，不在文件算法中散落埋点。

## 后果

- 正面：不产生大量逐文件操作 span，保留进程运行健康指标。
- 负面：不能据此定位具体 readdir/lstat/realpath 调用的耗时或异常。
- 边界：历史 fs 记录不删除，正常保留与轮转；指标不是业务结果或单次请求的根因证明。

## 后续范围确认（2026-09-14）

用户确认继续独立沙箱 instrumentation，兑现上述“下一项”：在公共启动、请求及进程事件边界集中观察 init、execute、timeout、invalidate、close、exit，并以沙箱实例、worker 实例、代际和请求 ID 关联父工具与运行时指标。具体契约见 workflow-runs::REQ-066；不在各文件算法埋点，不引入 fs 插件或额外平台，不调整权限、deadline、重建和不重放语义。

初始化跨度与执行跨度分开；后者包含 IPC、worker 执行、宿主持久确认及结果校验，不是纯文件算法计时。故障首次归因与实际退出分开保存，迟到退出仍归旧 worker；诊断身份不是授权凭据或恢复真源。指标只关联进程，不把某次指标变化断言为某个请求的因果。
