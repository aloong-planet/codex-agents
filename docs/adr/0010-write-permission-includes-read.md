# ADR-0010: 写入授权包含读取

- 状态: 已接受(2026-09-07)

## 背景与问题

旧权限模型允许只写但不可读，与创建文件前的路径检查及创建后读取验证不一致。用户明确确认写权限应覆盖读权限，读取本身仍不能取得修改能力。

## 备选项

1. **写入包含读取，只读不包含写入**
2. 保留只写并由宿主代理路径元数据与原子提交——此前提出的修复方向，用户改为采用权限包含关系，不再引入此代理层
3. 保持只写创建失败——不能满足写入授权的预期，拒绝

## 决策

选定**方案 1**。替代 ADR-0002 的独立读写语义，保留安装或设置阶段授权、默认只读草稿、保存才生效、按模块和目录限制、运行中不得提权以及文件执行始终禁止等约束。有效授权只有无访问、只读和读写三种。保存写入时同时开启读取；撤销读取必须同时关闭写入。

既有只写配置在升级时原子迁移为读写，递增受影响模块的权限版本；重复重启不重复迁移。只读、零权限和未保存草稿不扩权。写入不包含执行、删除或绕过内容版本校验；覆盖和编辑仍须匹配内容 hash。

## 后果

- 正面：用户授权与文件创建、查找及读后验证一致，无需新增只写元数据代理。
- 负面：不再提供只能写入而不能查看内容的投递目录；既有只写目录的内容将可被该账户的已启用目标读取。
- 中性：关闭写入可以保留只读；微信渠道的发送限制、权限不足后的手动重试和 unknown 不重发规则不变。

- 用户在当前会话明确确认：“写权限应当覆盖读权限”。
