# Memory Curator 作用域与操作反馈设计

## 目标

Memory Curator 顶部必须在不展开高级信息的情况下说明当前操作作用域，并让每个控制动作都有立即、持续且可验证的反馈：

- 显示当前微信账户与当前入站目标的本地别名；没有别名时显示缩短 ID。
- 新发现的微信账户默认启用长期记忆。
- 用户主动停用后，重启或再次发现账户不得自动重新启用。
- 启用、停用、设置计划提醒接收人均显示处理中、成功或失败回执。
- 按钮文字和禁用状态反映服务端真实状态，而不是只反映上一次点击。

## 状态模型

账户记忆状态从 v4 升到 v5：

```ts
{
  version: 5,
  knownAccounts: string[],
  enabledAccounts: string[],
  disabledAccounts: string[],
  ...
}
```

`registerAccount(accountId)` 是发现账户的唯一入口：

1. 首次发现且不在 `disabledAccounts` 中：加入 `knownAccounts` 和 `enabledAccounts`。
2. 已启用账户：幂等，无写入。
3. 用户曾主动停用：只确保已知，不重新启用。

`enable` 会从 `disabledAccounts` 移除账户；`disable` 会加入 `disabledAccounts`。迁移 v4 时，把 `knownAccounts - enabledAccounts` 解释为用户已停用，以免升级后意外恢复记忆采集。

WeixinCodexService 启动时注册当前通道内全部账户；每条入站消息进入处理前再次注册，覆盖服务运行期间新增账户的路径。

## 公共状态

`planFollowUp` 增加可选 `reminderTarget`。它只返回面板本来已经能够显示的当前微信目标 ID，用于判断“当前所选目标”是否就是已确认接收人，页面不读取或展示任何 token。

## 页面行为

Memory Curator 顶部增加作用域卡：

- 当前账户：本地别名或缩短 ID。
- 当前目标：本地别名或缩短 ID；没有目标时显示“尚未选择”。
- 账户卡右侧固定显示“已启用”或“已停用”；目标卡右侧固定显示“已设置”或“未设置”。状态来自当前服务端快照，点击回执仍单独显示在按钮下方。

按钮状态：

- 已启用：启用按钮显示“记忆已启用”并禁用；停用按钮可用。
- 已停用：启用按钮可用；停用按钮显示“记忆已停用”并禁用。
- 当前目标已绑定：提醒按钮显示“当前目标已设为提醒接收人”并禁用。
- 目标未绑定：提醒按钮可用。

按钮下方紧邻放置 `role=status`、`aria-live=polite` 的反馈区。点击后先显示处理中，成功后显示明确完成态；失败时在同一区域显示安全错误信息。切换账户或目标时清除上一作用域的反馈，避免误读。

## 失败模式

- 页面没有账户：三个按钮禁用，作用域明确显示未选择。
- 页面有账户但没有入站目标：记忆默认启用，提醒按钮禁用，目标显示未选择。
- API 失败：按钮恢复，反馈区显示失败，页面刷新到服务端真实状态。
- 轮询刷新：成功回执不被普通刷新清空；仅作用域变化时清空。
- 旧状态升级：用户原先停用的账户保持停用。

## 验证

- 单测：首次注册默认启用；停用持久化；旧 v4 停用迁移；提醒目标公开状态。
- 服务测试：启动与入站都会注册通道账户。
- E2E：页面显示账户/目标；默认已启用；停用、启用、设置目标均有可见反馈和正确按钮状态。
- 浏览器实测：在 `http://127.0.0.1:4317/` 核对真实账户/目标和按钮状态；三种控制点击在隔离 fixture E2E 中验证，避免为了验收短暂停用真实账户记忆。
