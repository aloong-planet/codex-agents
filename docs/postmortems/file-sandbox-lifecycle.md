# 文件沙箱：死亡进程不能由已成功的 ready Promise 代表

2026-09-13

## 因果链

沙箱实例按回合复用，但 ready 只缓存初始化结果。超时/退出后旧实例仍被认为已初始化，因此同回合后续调用继续使用不可用进程。只清 ready 也不够：旧进程的迟到 exit 会清掉新请求；初始化错误回复若只重置 Promise，则旧进程仍存活。

最初生产请求为什么超过 5 秒尚无阶段证据；本复盘仅解释故障后的重复失败，不把合成 SIGSTOP 解释为生产触发原因。

## 检查盲区

既有 file-sandbox.test.ts 的用例覆盖查找、读取、权限、写入竞态、快照与大结果拒绝，但没有“同一对象遭遇进程超时或死亡后立即继续查询”的序列。新一轮或新实例成功不能验证旧对象生命周期正确。

## 防御

- 当前子进程身份作为代际门禁；所有异步回调只能影响所属代际。
- 超时、退出和初始化失败清 ready、帧缓存及等待者；下一次显式调用重建。
- close 永久禁用且有界；正常领域错误不重启。
- 失败调用不自动重放。替换已完成但回复挂起的用例确认只修改一次。
- 固化真实 worker 的故障回归、同回合 ToolHost 集成和旧事件污染变异检查。
