# 腾讯转写唯一语音输入设计审查

## 审查结论

设计可实施，且比“先保存再删除”更可靠：原音在入口即被排除，避免异常、崩溃或删除失败造成残留。

## 已检查风险

- **只改 `buildInput` 不够**：仍会下载并保留本地原音；因此必须同时修改渠道 materialize 过滤。
- **只改渠道不够**：fixture 或未来调用者仍可能注入 voice attachment；因此输入层必须二次拒绝。
- **引用语音遗漏**：主 item 与 `ref_msg.message_item` 共用同一 materialize helper；过滤必须覆盖两条路径。
- **无转写行为回归**：当前在 materialize 前就返回拒绝，保持现有顺序即可。
- **媒体功能误伤**：仅过滤 voice；图片、文件、视频和引用媒体逻辑保持。
- **既有历史误解**：本改动只阻止新增音频，不清理既有 Codex rollout；交付时必须明确。
- **删除能力范围**：不删除 `IlinkMediaStore` 的 voice 转码实现，避免扩大到无关重构；生产路径测试证明它不再被调用。

## 设计修正

最初“处理结束后删除原音”的设想调整为“能使用腾讯转写时根本不下载原音”。这消除了临时文件删除 race，也更符合用户要求的不做自有语音识别。
