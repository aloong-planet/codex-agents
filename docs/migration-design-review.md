# codex-weixin 独立仓库迁移设计审查

## 审查结论

设计可以进入实现，但必须遵守以下门禁。

## 已发现并修正的问题

1. **直接移动会让 4317 立即中断。** 改为先复制、离线验证，再执行短暂停机切换。
2. **只修改插件源码不会刷新 Codex cache。** 加入 cachebuster、marketplace 切换与重新安装步骤。
3. **直接改 `~/.codex/config.toml` 违反配置边界。** 改为只通过 Codex CLI 管理 marketplace 与插件。
4. **把 Application Support 一起搬入仓库会泄露凭据。** 明确排除全部私有运行状态，并保持原路径不变。
5. **迁移期间 scheduler 可能正在发送。** 切换前必须读取公开运行状态；处于发送中或发送结果未知时不得切换。
6. **停止子进程不足以停止 keepalive job。** 切换必须针对精确 launchd label bootout，再创建新 label。
7. **新 cwd 会改变页面中的授权目录。** root ID 保持 `workspace`，显示路径更新为新后端目录；Vault root ID 保持不变。
8. **新插件与当前任务的旧插件可能并存。** 自动验证使用 CLI 与 fixture；真实 Codex UI 验证要求新建任务。
9. **立即删除旧目录会失去快速回滚。** 本次只把新仓库设为权威来源，旧目录暂留；删除另行确认。

## 实现约束

- 不读取或打印 token、账户秘密和微信正文。
- 不触发登录、二维码、真实入站或真实发送。
- 不改 OpenClaw 凭据、账户配置、cron 或腾讯插件源码。
- 不在旧 OpenClaw 工作树中清理无关脏文件。
- 所有 JavaScript 依赖和脚本使用 pnpm。
- 只在切换服务确实必要时重启，并确认唯一 listener。

## 审查后的成功定义

“迁移成功”必须同时满足：新仓库测试全绿、新 marketplace 安装有效、新服务从新路径运行、4317 状态 API 正常、外部状态连续；仅复制文件或仅打开页面都不算完成。

## 实现后复审

- 发现 `.mcp.json` 虽已改到新目录但仍为绝对路径，会让安装缓存依赖源码位置。已增加先红后绿的插件包测试，并改为 `cwd: "."` 与 `args: ["dist/server.mjs"]`。
- 增加权限候选回归断言，确保页面第一授权根显示为 `codex-weixin 项目` 且路径来自新服务 cwd。
- 全量测试和两个独立 E2E 边界均重新执行，没有以旧路径或旧插件缓存造成假通过。
