# Memory Curator 作用域与操作反馈设计审查

## 审查结论

方案可实施。默认启用必须通过显式 `disabledAccounts` 区分“从未选择”和“主动停用”，否则任何自动注册都会在重启后覆盖用户选择。

## 已补强点

1. **默认启用的发现路径**：仅在 UI 渲染时推断不够，后台接收消息时也必须已经启用，因此注册放在服务启动和入站处理入口。
2. **旧数据迁移**：v4 中已知但未启用的账户按主动停用迁移，避免升级造成隐私边界扩大。
3. **提醒按钮真值**：单一 `targetConfirmed` 无法判断当前选择是否为接收人，公共状态必须返回实际绑定目标供本地比较。
4. **轮询覆盖反馈**：反馈不能从服务 notice 推断，也不能每次 render 重置；使用独立页面状态，作用域变化才清除。
5. **失败可见性**：全局错误条离按钮较远，操作区必须直接显示失败，同时保留全局错误兼容原路径。
6. **固定状态与瞬时回执分离**：作用域卡的徽标只表达当前真实状态，按钮下方反馈只表达最近一次操作结果；轮询刷新更新前者，但不吞掉后者。

## 不做事项

- 不改变记忆文件、事件结构或 Curator 决策逻辑。
- 不自动发送提醒或微信测试消息。
- 不展示原始 token、凭据或未缩短的 ID。
- 不重启正在运行的开发服务。
