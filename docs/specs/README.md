# 功能规格

`docs/specs/` 保存仍然有效的功能需求全景：问题、用户故事、失败模式、抽象实现决策、测试 seam 和明确不做。每个功能只由它的 spec 描述，一个 slug 对应一个功能；功能尚未实现时用可验证的 `Pending:` 注记，不把计划中的能力写成已存在；功能移除时删除它的 spec 和索引行。

spec 就地维护现行描述，不记录变更史（历史见 git），不引用临时票、分支或原型路径。架构取舍只引用 ADR 编号；实现完成后，spec 应与实现、ADR 和 `CONTEXT.md` 一致，术语取自 `CONTEXT.md`。
