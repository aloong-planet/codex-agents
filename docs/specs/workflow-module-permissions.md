# 工作流模块权限

> 关联：ADR-0010 · ADR-0008 · ADR-0029

## Problem Statement

主微信 Codex 直接获得通用文件工具后，单纯依赖模型遵守目录提示或在进程内做字符串路径判断不够可靠。系统需要把已经保存的模块目录授权变成文件工具的实际运行边界，同时保持写入包含读取、只读不写、默认不写、运行中不提权和始终禁止执行。

## Solution

保留安装、首次启用和“本地权限”设置页中的 module/scope 授权真源。文件工具运行在专用 File Sandbox Adapter 中；生产 Adapter 使用独立 Node 子进程及当前运行时的 Permission Model，只运行随应用打包的可信固定代码，并授予代码自身、当前 permission revision 对应的读取/写入根目录及专属内部 spool 所需的最小权限，不授予网络、child process、worker、native addon、WASI 或执行能力。Node Permission Model 是纵深防护，不是运行恶意代码的强安全隔离。

“本地权限”页按模块分区显示可配置的目录范围（笔记目录与本地媒体目录各在一区），只能调整宿主已登记目录的读写，不能提交任意路径；新增任意目录的本机选择器尚未开放。点击“保存更改”后显示“已配置”和明确反馈；基于旧版本页面的保存被拒绝，不静默覆盖更新后的配置。保存权限本身不读取、修改或发送任何文件。已授权目录中的服务状态与配置不进入任何文件授权，见 [workflow-runs::CON-003](workflow-runs.md)。

宿主通过结构化 stdio Interface 调用沙箱，不提供 shell。沙箱池按账户、模块和 permission revision 隔离；跨模块查询由宿主分别调用对应沙箱并合并结构化结果，不把多个模块的根目录合并成一个进程权限。权限 revision 改变时只替换对应模块的沙箱进程；旧进程只完成已经绑定旧快照的调用，不能接收新调用，随后退出。微信通道不读取用户原始路径，只消费沙箱生成并由宿主持久登记的不可变发送快照。

## User Stories

1. As a 用户, I want 文件工具只能访问我保存过的目录, so that 模型不能越过设置页授权。
2. As a 用户, I want 默认读取开启、写入关闭，写入包含读取, so that 查看文件不会自动获得修改能力。
3. As a 用户, I want 改变授权后下一次操作立即使用新权限, so that 已撤销目录不会继续可见。
4. As a 用户, I want 脚本和二进制始终不能执行, so that 写入权限不能升级为代码执行。
5. As a 维护者, I want 沙箱拥有小而稳定的 Interface, so that 文件算法和进程隔离可以分别测试和替换。
6. As a 用户, I want 撤销读取权限后旧模型会话不再保留文件正文, so that 停止访问不仅限制新工具调用。
7. As a 用户, I want 权限页说明读取结果会进入 Codex 会话且账户授权供哪些目标使用, so that 保存授权前能够理解实际数据边界。

## 失败模式与边界

1. 没有任何读取 scope：`files.find/grep/read` 返回权限不足，不退回全盘或 workspace。
2. 写入包含读取：保存写入授权时同时授予读取，可查找、读取、原子创建和基于内容 hash 修改文件。取消读取但保留写入时仍可读取；撤销读取必须同时关闭写入。旧版只写授权迁移为读写并递增对应模块 revision，重启不重复迁移；只读和零权限目录不扩权。
3. `files.edit` 或覆盖现有文件：必须同时具备读取和写入授权及匹配的内容 hash。
4. 父子 scope 权限不同：以命中路径最具体的显式 scope 为准；不得借父目录扩大被子 scope 拒绝的访问。
    > Pending: `files.*` 文件工具尚未执行这一条。读写都关闭的子 scope 不进入回合的授权目录清单，但包含它的可读授权目录仍能经 `files.find/grep/read` 查找、搜索和读取其中的文件；写入也只按调用所用的 scope 判定，不受权限更少的子 scope 限制。
5. scope 被移动、删除或替换为符号链接：调用失败关闭，不自动改绑相似路径。
6. 相对路径包含 `..`、NUL、绝对前缀或平台设备路径：在进入文件系统前拒绝。
7. 目录遍历遇到符号链接、mount、特殊文件或循环：不跟随，不把其目标签发为 reference。
8. 已签发 reference 过期、scope revision 改变或目标不再是同一普通文件：认证层仍可取得其冻结资源身份用于幂等查询，但新读写和发送必须拒绝；不得解析为新路径。
9. 权限保存与调用并发：调用固定使用开始时的 revision；撤销后尚未开始的调用不能进入旧进程。
10. 沙箱进程崩溃、超时或协议返回畸形：结束本次文件调用并记录脱敏阶段，不把失败解释为没有匹配。
11. 沙箱被要求启动子进程、加载 native addon 或执行文件：运行时权限和 Interface 双重拒绝。
12. 沙箱输出绝对路径、文件正文超预算或未知字段：宿主结构校验拒绝结果，不转发给模型。
13. 写入中途崩溃：prepared 但未替换可安全终止；已经原子替换但结果未返回时按前后 hash 对账，不把未确认结果盲目重做。
14. 权限页预选但用户未保存：不得进入沙箱根目录集合。
15. 用户保存新权限：只影响后续工作流，不自动恢复因权限不足已经结束的旧 Run。
16. 用户收窄或撤销读取 scope：递增账户访问上下文代际，并轮换该账户已启用目标的 App Server thread；旧文件正文、grep 片段和自动摘要不复制到新 thread。
17. 用户扩大读取 scope：下一回合使用新 revision，不因单纯扩权轮换 thread。
18. 账户存在多个已启用目标：账户级目录授权可被这些明确启用的目标使用；未启用目标的入站不能进入 Agent Tool Host。
19. 沙箱需要生成发送快照：只允许写入该账户、模块和 revision 专属的私有 spool，不因此获得用户 scope 的写入权限。
20. spool 超过账户配额、快照写入失败或 manifest 未持久化：不创建发送 Run，不转移 owner，也不重新打开原始路径兜底。
21. `files.write` 的相对路径以 scope 的显示标签加 `/` 开头：显示标签是该授权目录本身的名称，也是结果里 `displayPath` 的第一段，所以这样的路径是按名称指向这个授权目录，文件落在去掉显示标签之后的路径上，不在根目录下新建同名子目录。
    - 授权根目录下已经有与显示标签同名的条目（目录、文件或符号链接，不跟随符号链接）时，路径按字面处理，不去掉显示标签：文件落在这个同名条目之内，条目不是目录时写入被沙箱拒绝。同名条目不论怎样产生都算，包括一次写入自己建出的同名目录（相对路径为 `显示标签/显示标签/a.md` 时，第一次写入建出它）；要让按名称的写法在这个授权目录里重新落到根目录之下，必须先移走这个条目。无法确定有没有这个条目时（查询失败且不是“不存在”，例如显示标签含 `/` 而其第一段处是一个文件）同样按字面处理。
    - 判定按每次调用时授权根目录的实际状态做，不沿用上一次调用的判定。
    - 只认以完整显示标签加 `/` 开头的路径，不做大小写或 Unicode 归一；路径中间出现的同名段、只以显示标签为前缀的首段（如显示标签为 `demo-vault` 时的 `demo-vault-2/`）、以及正好等于显示标签的整条路径都按字面处理。显示标签本身含 `/` 时，去掉的是整个显示标签。
    - 宿主先拒绝绝对路径和含 `.`、`..` 或空段的路径，再做判定；第 6 条的其余校验（如 NUL）由沙箱在判定之后执行。去掉名称后的路径照常经过沙箱的全部检查，包括 [workflow-runs::CON-003](workflow-runs.md) 的受保护集合，不扩大可写范围。
    - 操作日志的幂等键使用判定之后的路径：两次调用的判定相同时，同一次写入重试时带名称与不带名称的两种写法是同一个操作，不写第二次。两次调用之间根目录下出现了同名条目的，重试时带名称的写法改按字面处理，是另一个路径上的另一个操作：它在同名条目之内再写一份，完成效果证据按两次写入计。
    - 写入结果返回实际落点的 `relativePath` 与 `displayPath`。
    - `files.find/grep` 的 glob 不做这一转换：以显示标签开头的 glob 仍按字面匹配根目录之下的相对路径。

## Implementation Decisions

- `FileSandbox.execute(operation, trustedAccessSnapshot)` 是 Local File Tools 的内部 Interface；生产进程 Adapter 与测试 Adapter 都实现它。模型和上层调用者不知道真实根路径、遍历方式、spool 路径或 Node 权限参数。
- 生产 Adapter 启动单独 Node 进程，启用 enforce 模式的 `--permission`，分别生成最小 `--allow-fs-read`、用户 scope `--allow-fs-write` 与专属内部 spool 写入范围；不传递允许网络、child process、worker、addon、WASI、FFI 或 inspector 的开关。
- 沙箱代码构建为独立入口且不可加载动态插件、模型生成代码或用户脚本；除自身只读运行文件、明确授权根目录和专属 spool 外，不授予其他文件系统范围。进程通过长度前缀 JSON 消息通信，schema 严格且每条请求有 deadline、request ID 和最大消息体。
- 沙箱池以 `account + module + permission revision` 为隔离键，每个进程配置不可变。跨 scope 查询可以在同一模块进程内完成，跨模块查询由 Local File Tools 聚合；任何单个进程都不能读取另一模块的授权根。
- 新 revision 采用先启动新进程、通过自检、再切换新请求的方式；旧进程排空后关闭。启动失败继续保留旧进程只服务已绑定旧 revision 的调用，新调用失败关闭。
- opaque reference 由宿主 reference store 签发并绑定 account、module、scope、permission revision、相对身份、文件元数据和 expiry；模型与沙箱都不能把任意字符串升级为授权。
- reference 的认证身份与实时可用性分开：认证身份可以在内容变化后用于定位同一操作日志，实时文件访问仍须通过当前权限、revision、类型与 hash 校验。
- 内联修改操作日志由宿主持久化，沙箱只执行 prepare/commit/reconcile；沙箱进程状态和未提交的临时文件均不是状态真源。
- 发送快照采用随机不可猜名称、`0600` 权限和持久 manifest，绑定账户、目标、资源身份、sha256、大小与安全文件名。快照句柄默认保留 24 小时；服务启动时删除过期句柄对应快照与未被有效句柄引用的孤儿快照。unknown 不自动重发，也不另行延长保留期。每个微信账户的快照总量上限为 512 MiB，超限时预检失败且不创建 Run。
- 文件工具的预算在宿主和沙箱两侧同时限制；宿主限制整个模型回合聚合值，沙箱限制单次扫描、单文件、正则和输出值。
- 设置页与 SQLite 仍是授权真源；沙箱进程状态只是可重建投影，服务重启后从持久权限重新创建。
- 当前运行时已提供 Node Permission Model；实现阶段必须用真实越界访问测试证明它实际拒绝未授权路径，不能只断言启动参数。该验证只证明可信固定代码的能力约束，不升级为抵御进程内恶意代码或同一 OS 用户恶意竞争的承诺。

## Testing Decisions

- 主 seam 是生产 File Sandbox Adapter 加真实临时目录。测试从 Interface 发请求，并在授权根内外放置同名文件，证明越界文件永远不可见和不可读写。
- 覆盖只读、写入包含读取、旧版只写迁移、零权限、父子 scope、撤销/扩权 revision、符号链接、路径穿越、特殊文件、超时、崩溃、畸形协议、原子创建、CAS edit、prepare/commit 对账、spool 配额、孤儿快照与进程切换。
- 覆盖读取后撤权导致 thread 轮换、扩权不轮换、多个已启用目标共享账户授权以及未启用目标无法进入文件工具宿主。
- 至少一个反向安全测试直接让沙箱实现尝试读取未授权哨兵文件并断言运行时拒绝；仅测试宿主预校验不算沙箱通过。
- 权限 UI 布局没有变化；增加“读取结果会进入当前 Codex 会话”和“账户目录授权适用于该账户下已启用目标”的纯说明文案，并回归现有模块卡片、默认读写、保存反馈和持久化。新增目录控件留到对应功能实现时另走原型门。

## Out of Scope

- 为微信通道、数据库、普通模型调用或整个 App Server 加同一个文件沙箱。
- 网络沙箱、容器、虚拟机或跨平台强隔离承诺。
- 运行中授权弹窗、会话临时提权或模型自行修改权限。
- 文件删除、移动、执行、解压、安装、chmod、所有权修改和系统目录授权。

## Further Notes

- File Sandbox 是可信固定文件实现的受限 Adapter，不是业务 Provider、查询 Resolver、第二个 Agent，也不是可运行不可信代码的通用安全容器。
- macOS Photos Library 仍是不可进入的系统隐私边界；其他普通目录只依据保存授权和真实文件类型处理，不用文件扩展名穷举跳过。
